## The hard part is the schema

Most text-to-SQL demos assume a small, clean database with obvious column names. Dynamic Data Agent is being built for the opposite situation: an unfamiliar database dump where relationships are implied, naming is inconsistent, and nobody has time to write a semantic layer by hand.

The agent ingests the schema, infers relationships, and builds the context needed to translate a question into a query. The work is as much about validation as generation: deciding what the model is allowed to assume, how to detect an unsafe query, and when to ask for clarification.

## A deliberate work in progress

This project is still in development. The goal is not an unbounded agent that can execute anything. It is a bounded assistant that can explain what it found, show the query it wants to run, and return a result that a user can verify.

The private case study will be updated as the execution model and interface mature. The current implementation is a Python backend with SQLAlchemy and support for SQLite and MySQL sources.
