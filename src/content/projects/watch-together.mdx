## Watch together without uploading the file

Watch parties usually force a trade-off: upload a large video somewhere, or share a screen and accept degraded audio and a desktop that is locked into the job. Watch Together takes a third path. The host opens a local file in their browser, and the browser captures the playing video and sends it directly to each viewer over WebRTC. The server only coordinates rooms, participants, and signaling.

The result is intentionally local-first. There are no accounts, the video never lands in server storage, and the host remains in control of playback. Late joiners pick up the current position instead of starting from the beginning.

## The player is part of the product

A watch party is only as good as its player. The custom player covers the expected controls, but also handles multiple audio tracks, embedded and external subtitles, picture adjustments, screenshots, picture-in-picture, theater mode, and a stats overlay. It supports mouse, touch, and keyboard interactions, and it keeps those controls operable when the player enters fullscreen.

The playback engine chooses the cheapest path it can: native playback first, lossless remux for containers the browser cannot read directly, and FFmpeg.wasm as the fallback for everything else. Audio tracks the browser cannot decode are converted in the browser rather than silently dropped.

## Calls, chat, and moderation

The room is not just a video surface. A separate peer-to-peer mesh powers audio and video calls, with a call that survives the host leaving. A text chat, participant roster, screen sharing, and host moderation tools make it usable for a small group rather than a one-way stream.

Kicks and bans are handled through a waiting-room flow, while playback permissions remain a host decision. Everything is designed around rooms of roughly two to ten people; the README is explicit that larger audiences would need an SFU instead of the current mesh.
