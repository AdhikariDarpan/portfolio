## From messy scan to usable fields

Document extraction fails at the edges: skewed phone photos, uneven lighting, stamps, handwriting, and layouts that vary between branches. This service was built to make that input usable before asking a model to interpret it.

The pipeline applies a sequence of OpenCV and Pillow preprocessing steps, extracts text with Tesseract, and then uses a cloud-hosted Ollama model to map the text into a requested schema. Pydantic models define the expected output so callers get a stable contract rather than free-form prose.

## Designed for integration

The service is a Flask API with a Docker-based delivery path. Configuration is externalized, prompts are kept explicit, and failures are returned in a form the calling application can reason about. This is intentionally a component, not a monolith: it can be dropped into an existing document workflow without dictating how that workflow is built.

The project is private because it contains client-specific extraction logic. The case study documents the engineering approach without exposing prompts, endpoints, or sample documents.
