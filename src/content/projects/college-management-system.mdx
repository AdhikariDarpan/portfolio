## One system, three audiences

A college management system only works if it is useful to the people doing different jobs. Students need results and schedules. Teachers need attendance and marks. Administrators need fees, reporting, and oversight. This project was built around those separate workflows without splitting into three disconnected applications.

The routine generator was a particularly interesting piece: class scheduling has hard constraints, teacher availability, room conflicts, and subject requirements. A backtracking approach provided a practical way to produce a valid starting schedule that staff could refine.

## Payments and records

Fee collection used local gateways, with transaction state reflected in the student record. Attendance, marks, and fee history were designed as related records rather than isolated screens, so a student profile could become a coherent view of progress.

The public repository is available as a reference implementation. It demonstrates the combination of academic administration, scheduling logic, and payment integration in a single Laravel and Python stack.
