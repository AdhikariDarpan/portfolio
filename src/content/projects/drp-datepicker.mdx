## One date, two calendars

Nepali products often need to display and accept dates in both Bikram Sambat and the Gregorian calendar. Most datepickers make the developer choose one calendar, hide the other behind conversion utilities, and then require manual wiring into forms.

DRP Datepicker treats both calendars as first-class. Every day cell shows the BS and AD dates together, a selection returns both representations, and the same conversion engine can be used without rendering a picker at all. The web package is a dependency-free Web Component; the Flutter package brings the same model to native forms.

## Web and Flutter, without divergent behaviour

The npm package ships a standalone conversion engine plus `<drp-datepicker>`, a form-associated custom element. It supports BS-first or AD-first modes, shared date ranges, fiscal-year helpers, month boundaries, multi-month ranges, custom formats, and theme tokens. Because it is a native element, it can be dropped into any framework without a wrapper.

The Flutter package implements the same interaction model for mobile and desktop apps. It supports controlled and uncontrolled selection, holidays and typed events, disabled dates, Saturday highlighting, Devanagari digits, and validation inside a Flutter `Form`.

## Small surface, careful edge cases

The hard part is not drawing a calendar. It is keeping month boundaries, supported date ranges, Nepali digit formatting, form values, and accessibility behaviour consistent across two ecosystems. The packages deliberately avoid heavy date libraries so the conversion rules stay visible and testable, and both expose the core calendar engine separately from the UI for server-side or non-visual use.
