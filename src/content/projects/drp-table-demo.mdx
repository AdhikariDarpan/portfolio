## A demo that treats the library like a consumer

DRP Table is being packaged for direct browser use, so the demo cannot rely on a bundler, a framework wrapper, or a special build step. It loads the main bundle, UI helper, theme stylesheet, export bundle, and worker script as separate files, then wires them through the globals a CDN consumer would actually receive.

That constraint is the point. A library can look clean inside its own monorepo and still be awkward when someone includes a script tag and tries to use it. The demo exposes those integration details early, including load order, theme setup, and the difference between the browser and worker bundles.

## Large data without blocking the page

The demo generates 100,000 fake rows to test the table under a workload that a small example would never reveal. Worker mode moves sorting and filtering into a separate classic worker script, keeping the interface responsive while the dataset is processed.

Basic table behavior can run from `file://`, but browsers block worker scripts from local files. The included static server exists so the worker path can be tested the same way it would run on a real site.

## Still under development

The table, theming, export, and worker paths are functional, but the project is not finished. It is being used to find integration gaps and rough edges before the library is treated as complete. The repository is private while that work continues, so there is no public demo link yet.
