## One method instead of twenty

Most image libraries expose a separate function for every operation. DRP keeps one entry point: pass a source and any combination of options, and the SDK builds the correct pipeline. Resize, crop, rotate, flip, adjust, filter, encode, and metadata handling happen in a defined order without the caller having to assemble it.

The source can be a `File`, `Blob`, URL, image element, or canvas. The result is a blob plus the output dimensions, format, quality, and size. That makes the SDK useful in upload flows, editors, and browser tools without tying it to a framework.

## Compression as a budget

`targetSize: "500KB"` is the idea that shaped the package. Instead of exposing only a raw quality slider, the compressor searches across quality levels to land inside a requested file-size budget. Presets for web, email, print, and thumbnails cover the common cases, while a preview API estimates savings before the expensive work begins.

The editor adds non-destructive crop, resize, transform, adjustment, filter, and layer operations with undo and redo. A separate batch API applies one operation across a list of files, and export presets map directly to common social-platform dimensions.

## Built to be dropped in

The package ships typed ESM and UMD builds, modular imports for tree-shaking, and a CDN bundle that exposes `window.DRP`. It works in modern browsers, including worker-backed processing where the platform supports it, and keeps the API consistent whether the caller needs one image or a batch.
