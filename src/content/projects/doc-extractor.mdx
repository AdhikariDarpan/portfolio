## Extraction without a model dependency

Doc Extractor is an invoice and document extraction API designed to run from a plain Python environment. It accepts an image or PDF, applies a fixed preprocessing pipeline, reads the text, and returns structured fields and tables through a simple Flask endpoint.

The primary OCR engine is PaddleOCR, with EasyOCR as a fallback when the first pass fails. That choice avoids Tesseract binaries and Docker while still giving the pipeline a second engine for difficult scans. PyMuPDF handles PDF pages directly, so no external PDF renderer is required.

## Rule-based parsing for messy invoices

OCR alone returns a crowd of words. The useful work happens after recognition: line grouping, spatial relationships, alias matching, and table reconstruction. The parser can find a value to the right of a label, below it, or through a fuzzy context query when the layout is less predictable.

A five-stage OpenCV and Pillow pipeline improves contrast and geometry before recognition. Table headers are detected again mid-document when a new table begins, and common label variants such as `inv no`, `bill no`, `sub-total`, and `grand total` map into stable field names. Every response includes the OCR engine, confidence, word count, and warnings so a caller can decide whether to trust the result.

## Optional intelligence, predictable core

The rule-based extractor always runs first. An optional LLM layer can fill gaps when enabled, but it is not part of the default path and cannot silently replace the deterministic output. That makes the service easier to test, cheaper to run, and safer for documents that should not leave the local environment.

The repository is private because it contains extraction logic tuned around real invoice layouts. The case study focuses on the pipeline and response contract without publishing sample documents or client data.
